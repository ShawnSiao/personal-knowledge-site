# 建立一个可出版的 Agent 知识库

## 要解决的问题

本地资料通常同时包含项目代码、工作记录、私人数据、第三方材料和可以公开复用的方法。如果把整个目录直接交给静态网站生成器，检索很方便，误发布风险也会随之扩大。

一个可长期运行的知识库需要同时满足三件事：保留原始证据、支持 Agent 关联知识、能够安全地选择性出版。

## 三层结构

### 私有来源层

来源层保存项目清单、来源位置、盘点时间和证据类型。它回答「结论从哪里来」，但默认不公开。代码仓库、历史记录和原始材料只作为只读证据，不复制进知识库。

### 私有知识层

知识层包含概念、实体、案例、方法、文章和综合结论。每个页面使用稳定 ID，并记录状态、可见性、相关页面、来源引用和置信度。这样既能支持全文检索，也能形成可遍历的知识图谱。

### 公开出版层

公开站是经过筛选的生成结果，不是私有知识库的镜像。页面必须同时满足：

- 状态为已发布；
- 可见性为公开；
- 已完成内容审核；
- 存在稳定的发布路径；
- 正文不含本地绝对路径、凭据和受限材料。

导出时只保留公开字段，内部来源位置、审核记录和私有元数据不进入网站仓库。

## 为什么使用两个 Git 仓库

私有知识库和公开网站的风险模型不同。分成两个仓库后，版本历史、访问权限和自动化流程也随之分开：

- 私有仓库记录完整知识演进；
- 公开仓库只记录允许发布的内容和网站代码；
- GitHub Pages 只接触公开仓库；
- 发布错误可以在导出阶段被拦截，而不是等到网站上线后再发现。

## 更新流程

一次完整更新遵循以下顺序：

1. 只读盘点新增或变化的来源。
2. 把材料整理为来源页、概念页、案例页或文章。
3. 标记冲突、重复信息和待验证结论。
4. 完成公开边界与事实检查。
5. 运行知识库验证器。
6. 将白名单页面导出到公开站。
7. 构建网站并检查链接、搜索和页面结构。
8. 分别提交私有知识库与公开网站。

## 适用边界

自动检查适合发现结构缺失、本地路径和常见凭据模式，不能替代版权、人物隐私和争议事实的人工判断。高风险材料应长期留在私有来源层，只公开重新表达后的方法结论。
