# 重排序与上下文组装：把有限位置留给证据

假设检索返回 30 个候选，其中只有 4 个真正支持回答。把 30 个全部交给生成模型，会增加成本和干扰；只取前 3 个，又可能遗漏关键例外。重排序负责在候选中重新判断相关性，上下文组装负责在预算内选择完整证据。

两者不同：相关性高的片段不一定需要全部保留，重复出现的同一条规则也不等于多份证据。

## 1. 两阶段检索为什么常见

初次检索要面对整个资料集，通常优先速度和召回。重排序只面对较小的候选集，可以使用更昂贵的判断方式。

双编码器分别编码问题与文档，便于预先计算文档向量。交叉编码器则把问题与候选一起处理，能够直接建模两者关系，但不能像独立文档向量一样一次编码后用于所有查询。Sentence Transformers 官方文档用这一差异解释「先检索，再重排序」的流程。[Retrieve & Re-Rank](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)

重排序无法找回初次检索从未返回的证据。如果前 50 个候选里没有答案，换一个重排序模型也无济于事。因此先看候选召回，再看前排质量。

## 2. 接入模型时先固定输入和输出

下面是神经重排序的接入示意，需要安装 FlagEmbedding 并下载模型；本次离线实验没有执行此模型，也没有测量其延迟或效果。

```python
from FlagEmbedding import FlagReranker

model = FlagReranker("BAAI/bge-reranker-v2-m3", use_fp16=False)
question = "回滚前需要什么批准？"
candidates = [
    {"id": "approval", "text": "发布回滚需要值班负责人批准。"},
    {"id": "health", "text": "回滚结束后检查服务健康状态。"},
]
pairs = [[question, item["text"]] for item in candidates]
scores = model.compute_score(pairs)
ordered = sorted(
    zip(candidates, scores),
    key=lambda pair: (-float(pair[1]), pair[0]["id"]),
)
print([item["id"] for item, _ in ordered])
```

模型卡说明，该模型以问题与文段为输入，返回相关性分数。[BGE 模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3) 这里不预先填写运行输出。分数即使通过 sigmoid 映射到 0–1，也不能直接解释为答案正确率。

候选过长时还要检查截断：如果审批条件恰好被截掉，重排序模型实际看见的就不是完整证据。应记录模型输入长度，并在必要时拆分或补充关键条件。

## 3. 上下文预算要显式计算

可以按下面的方式分配预算：

```text
可用证据预算
= 模型上下文上限
- 系统规则
- 问题与必要历史
- 预留输出
- 安全余量
```

具体数值取决于模型与业务。预算应由 tokenizer 计算，不要把字数当成 token 数。工具结果、引用标签和文档标题也占空间。

一个教学组装策略是：先按重排序结果排序，合并同文档相邻片段，去除高度重复的内容，再逐项放入预算。遇到长片段无法容纳时，不要从末尾任意砍掉一句话；可以改为更小的完整证据单元，或明确缺少哪些部分。

## 4. 相关性之外，还要处理覆盖与冲突

问题是「回滚前后分别做什么」时，只保留审批片段会漏掉回滚后的健康检查。因此需要检查问题的多个部分是否都有证据。

若两个有效来源对同一条件给出不同规定，去重算法不能把其中一个静默丢弃。应保留冲突关系，交给生成阶段说明，或请求确认适用范围。去重处理重复，不能代替权威性判断。

《Lost in the Middle》研究观察到，在其测试的模型与任务中，相关信息位于长输入中部时，表现可能下降。这个结果提醒系统需要测试信息位置与干扰，但不能推广为所有模型都具有相同曲线。[研究论文](https://arxiv.org/abs/2307.03172)

## 5. 为重排序设立失败时的行为

模型超时后可以退回融合排序，但必须记录本次降级。不能在日志写「已重排序」，实际却返回初次检索结果。若权限过滤后没有候选，重排序应直接跳过。

记录候选数、重排序耗时、输入长度、最终片段数和降级原因。单看总体响应时间，会隐藏究竟是检索慢、重排序慢还是生成慢。

## 本章练习与判断依据

为同一个问题准备相关主规则、相关例外、过期规则与无关片段。固定候选集合，比较「直接取前三条」和「按问题覆盖组装」的差异。

合格解释应指出：最终每个片段支持了问题的哪一部分，为什么保留或舍弃。若关键证据从未进入候选，应回到上一章排查，不继续调生成提示。
