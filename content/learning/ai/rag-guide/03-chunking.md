# 分块与索引：让片段既能命中又能读懂

「保留 30 天」是一段很短的文字，但脱离标题后无法知道保留的是备份、日志还是工单。分块的核心矛盾是：小片段容易精确命中，却可能缺少上下文；大片段保留关系，却引入更多无关信息。

因此，分块不是找一个通用数字后切到底，而是决定哪些信息必须一起出现。

## 1. 先确定答案需要的最小证据

对于「备份保留几天」，最小证据包括对象、时长和适用范围。对于「怎样回滚」，证据还需要审批条件、操作顺序与完成检查。两类问题可能需要不同粒度。

可以把标题路径附在每个片段上，例如「运维手册 / 数据保护 / 生产备份」。但标题与正文要分别存储：检索时可以共同编码，引用时仍显示真实原文，不能把系统自动补出的解释伪装成作者说过的话。

建议先采用段落边界，超过长度限制后再切分；表格保留表头，代码保留必要的函数或配置上下文。长章节可以采用父子片段：检索命中小片段，再按预算补取同一父段落。补取仍需检查权限，不能因命中了公开摘要就读取整个私有文档。

## 2. 重叠为什么有用，又为什么会浪费

假设句子被切在「恢复失败时」后面，下一块才是「停止自动重试」。没有重叠可能使两个片段都不完整。有重叠则有机会保留条件与动作。

但重叠会让多条检索结果重复出现同一句话，挤占生成预算，甚至让一个来源看起来像多份独立证据。召回后应检查片段是否来自同一文档、相邻区间是否重复，再决定合并。

下面是字符级实验切分器，不是模型 tokenizer。中文字符、英文单词和 token 不应按固定比例互换。

```python
def windows(text, size=120, overlap=20):
    if size <= 0 or not 0 <= overlap < size:
        raise ValueError("需要 size > overlap >= 0")
    start = 0
    while start < len(text):
        end = min(start + size, len(text))
        yield text[start:end]
        if end == len(text):
            break
        start = end - overlap
```

120 和 20 只是教学参数。上线时应使用目标模型的 token 计数工具，并将标题、元数据与正文一起纳入输入预算。微软的分块文档列出了固定长度、结构与语义等方法；具体参数仍需要围绕自己的资料验证。[官方分块说明](https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-chunk-documents)

## 3. 分块实验要固定什么

比较 120、240、480 字符三种方案时，保持问题集、源文档、检索方法和 Top-K 不变，分别记录：

- 正确证据有没有进入候选。
- 返回片段是否缺少条件或例外。
- 候选里有多少重复内容。
- 送入生成阶段的实际 token 数。

这是本站建议的实验设计，三个长度不是行业推荐值。如果一次同时换分块大小、嵌入模型与排序方法，结果改善了也很难归因。

## 4. 上下文补充能改善什么

Anthropic 在 2024 年提出为片段补充简短的文档上下文，再用于检索。其报告中，加入上下文嵌入与上下文 BM25 后，Top-20 片段检索失败率从 5.7% 降至 2.9%；再加入重排序后为 1.9%。其汇总使用表现最好的嵌入配置 Gemini Text 004，跨所列知识领域统计 1 − Recall@20。这些是厂商在其测试条件下的结果，不是本站复现实验，也不是回答准确率。[实验说明](https://www.anthropic.com/engineering/contextual-retrieval)

在纸舟案例中，可以先用确定性的标题路径补上下文，成本低且易检查。若使用模型生成背景摘要，就新增了一个可能出错的环节：模型可能把测试环境写成生产环境。因此应该保留原片段、补充文本、生成配置与审核结果，并分别存储。

## 5. 索引不是资料的最终真相

索引是源文档的一种可重建视图。除了文本与向量，至少要保存文档 ID、版本、分块 ID、标题路径、权限与来源定位。换嵌入模型时，不能把新向量直接混入旧索引；即使维度相同，两个模型的空间也不一定可比。

新的嵌入模型、分块规则和索引配置应一起生成一个版本。这样某次检索退化时，可以恢复旧版本并复查，而不是只能猜测「数据库最近不太稳定」。

## 本章练习与判断依据

把一条包含主规则、例外和生效日期的自编制度，分别切成三种大小。用「默认规则是什么」与「例外何时适用」两个问题查询。保留命中片段，检查条件有没有被截断。

合格结果不一定是最大块或最高命中率，而是能解释：为什么选这个粒度、付出了多少冗余、还有哪些问题需要父段落补充。
